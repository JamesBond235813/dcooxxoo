## 发布硬性规则

1. 不要从旧共享工作区构建或发布。它仍保留 83 组未提交/未跟踪改动，可能与生产 UI 不同。
2. 从干净的生产基线仓库建立独立工作树（`git clone root@66.94.122.149:/opt/dujiao-next-src <新目录>`）；发布改动先提交，绝不清理或覆盖旧共享工作区的未提交内容。
3. 禁止把本地仓库根目录整体 `rsync` 到生产目录；禁止在脏的生产源码树或旧共享工作区直接编译。
4. 进入发布前必须运行 `scripts/assert-production-release-safe.sh`。脚本会拒绝脏工作树、前后台源码或 dist 与锁定版本不一致、生产二进制哈希漂移等情况。必须设置 `EXPECTED_LIVE_BINARY_SHA256` 为刚从生产读取并人工核对的在线版本哈希。
5. 只有用户明确要求修改 UI 后，才可设置 `APPROVE_UI_CHANGE=YES`。执行前仍需人工审阅页面差异；环境变量不能代替用户授权。
6. 先构建候选二进制并校验，通过后再原子切换。发布前备份，发布后核对公网 `/health`、首页及相关资源；失败时恢复上一版二进制和资源。
